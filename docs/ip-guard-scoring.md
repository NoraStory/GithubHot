# IP 防护：防误判评分算法（iprisk）

> 实现：`internal/domain/iprisk`（纯算法，零 IO）· 接入：`internal/interfaces/httpapi/ipguard.go`
> 测试：`internal/domain/iprisk/iprisk_test.go`（算法）+ `internal/interfaces/httpapi/ipguard_risk_test.go`（引擎集成）

## 1. 为什么需要它：旧实现的三条误封路径

旧实现是「所有违规事件按 IP 线性求和，10 分钟窗口内 ≥100 分即封」+「部分事件标 `severe` 跳过累加直接封」。

| 误封路径 | 旧行为 | 触发场景 |
|---|---|---|
| 单规则磨分 | `rate` 每 5 分钟 +30 → 20 分钟内累计 100 → 封 | 公司网络 / 机场 WiFi / 运营商 CGNAT 共享出口，聚合上百正常用户 |
| 单信号秒封 | `headless-ua` 50 分标 `severe` → 立即封 7 天 | 隐私加固浏览器、自动化预览、客户端自报误判 |
| 密钥轮换 | 老 Cookie 签名失效 → 记 `id-forgery` 100 `severe` → 立即封 7 天 | **每次重启**（部署/OOM/未配 `IP_GUARD_SECRET` 时密钥随机生成）→ 全部老访客被封，且被封后全站 404 |
| 升级放大器 | 同一事件被多类事件反复触发 `ban()` → strikes 1→4 → 30 天 | 一次误判被放大成月级封禁 |

## 2. 算法：五条机制

```
每个事件：分数 × 0.5^(年龄/10min)   （半衰期衰减，窗口 40 分钟）
按「违规类型(kind)」聚合
  ├─ 弱证据类（R 速率 / P 协议 / E 环境核验）→ 乘共享出口稀释系数
  └─ 强证据类（I 身份令牌 / F 设备指纹 / A APP 签名）→ 不稀释（绑定设备，不随出口变化）
判定顺序：
  ① 持续滥用通道：任一类型稀释后原始分 ≥ 门槛 → 单独封
       强证据门槛 = 100（1× 阈值）
       弱证据门槛 = 150（1.5× 阈值，抵消"人多势众"）
  ② 常规通道：每类型贡献封顶（弱 40 / 强 70）→ 累加为有效分
       有效分 ≥ 100 **且** 不同违规类型 ≥ 2 → 封
```

**为什么这样设计**

- **单类上限（均 < 阈值）** 让"同一条规则反复计分"在结构上无法致封——这是误封的主要来源。
- **互证要求（≥2 种类型）** 对应"独立证据"：速率是共享出口的公共属性，必须叠加设备/协议层证据才说明是同一个作恶主体。
- **弱强分级** 承认证据归属力差异：令牌伪造、指纹劣迹、APP 签名绑定的是设备；速率和环境核验绑的是出口。
- **共享出口稀释**（`3/UA种类`，下限 0.4）用 UA 多样性近似"这条出口后面有多少人"。
- **持续通道** 保住真实判定：稀释保护的是"被分摊的噪声"，不是"独自持续胡作非为的人"。

## 3. 参数表

| 参数 | 值 | 说明 |
|---|---|---|
| `Threshold` | 100 | 封禁阈值（有效分） |
| `HalfLifeMin` | 10 | 事件衰减半衰期 |
| `DecayWindowMin` | 40 | 统计窗口（4 个半衰期） |
| `UADiversityFree` | 3 | UA 种类 ≤3 视为单一用户 |
| `DilutionFloor` | 0.4 | 稀释下限 |
| `WeakSoloFactor` | 1.5 | 弱证据单类封禁倍数 |
| `CapWeak` / `CapStrong` | 40 / 70 | 单类型贡献上限 |

## 4. 算例（均由单测锁定）

| 场景 | 事件 | 结果 |
|---|---|---|
| 单条 headless 环境核验 | `env-flag 50` | 不封（贡献 40，仅 1 类） |
| 脚本爬虫画像 | `rate 60 + env-flag 50 + bot-ua 25` | **封**（40+40+25=105，3 类互证） |
| Cookie 盗用 | `id-ip-drift 60 + device-mismatch 80 + env-flag 50` | **封**（170） |
| 代理池轮换 | `fp-linked 70 + fp-churn 40` | **封**（110，两种强证据） |
| 指纹碰撞受害者 | `fp-linked 70` 单条 | 不封（70 < 100，1 类） |
| CGNAT（30 种 UA） | `rate 30×8 + scanner 40 + bot-ua 25` | 不封（稀释后 64） |
| 单人持续高速率 | `rate 60×8`（40 分钟内） | **封**（单类 192 ≥ 150，持续通道） |
| 密钥轮换老 Cookie | `id-token-stale 15×3` | 不封（30 分，1 类） |
| 结构非法令牌 | `id-forgery` 100 | **即时封**（无歧义伪造，`severe`） |
| 流量攻击 | ≥600 req/min | **即时封**（无歧义） |

## 5. 引擎侧改动（配套）

1. `event()` 的非 `severe` 路径改走 `decideBan()`：取该 IP 近 80 条事件 → `iprisk.Evaluate`；取不到明细时回退粗口径且门槛抬到 150（宁可放过）。
2. `severe` 语义收窄为「无歧义的即时严重事件」：仅保留 **流量攻击** 与 **结构非法的身份令牌**。指纹连坐由 100/severe 降为 **70/非 severe**（碰撞误判防护）。
3. 令牌核验三态化（`verifyIDTokenEx`）：`tokenMalformed`（结构非法 → 伪造，即时封）/ `tokenBadSig`（结构合法签名失效 → 记 `id-token-stale` 15 分并重签）/ `tokenExpired`（正常重签）。
4. `flagScore` 全部去掉 `severe`（环境核验来自客户端自报，可伪造且会被出口分摊）。
5. `ban()` 幂等：进行中的封禁期内不再升级 strikes（消除升级放大器）。
6. 接近阈值时打观察日志（`有效分 / 类型数 / 稀释 / UA 种类`），便于灰度评估。
7. **环境核验按 flag 细分 kind**（`env-flag:<flag>`）：不同命中项成为独立证据参与互证，
   5 分钟去重也按 flag 粒度生效——否则所有 env 证据会被压成一条，互证永不成立
   （此项由活体验证发现，见 §9）。

## 6. 灰度与调参

- 观察日志阈值 60 分：上线后看 `[ipguard] 观察 …` 频次，评估是否有正常流量逼近阈值。
- 想放宽：调大 `Threshold` 或 `DilutionFloor`；想收紧：调小 `WeakSoloFactor`（1.5 → 1.2）。
- 所有参数为命名常量，改参数必须同步更新 `iprisk_test.go` 的算例。

## 7. 残余风险（本算法未覆盖，需另行处理）

1. **X-Forwarded-For 无条件采信**（`clientIPFromRequest`）：直连部署时攻击者可自填 XFF **栽赃**他人 IP，也可借此绕过自身封禁。建议引入 `TRUSTED_PROXY` 配置，默认不信任任何代理头。
2. **指纹碰撞**（同型号手机 / 同镜像电脑）：本算法把连坐降为 70 分（需互证），但更彻底的方案是检测"同一指纹短时间关联 IP 数暴增"以区分碰撞与真实换网。
3. **`admin-brute` 仍为 severe**（`auth.go`）：管理员连续输错 5 次密码即封 7 天（自救通道可解封，但普通管理员会懵）。建议降为 100 分非 severe，或对"已登录会话 IP"免计分。
4. **浏览器缩放改 DPR → 指纹变化 → `device-mismatch` 80 分**：属客户端指纹设计问题（`fingerprint.js:175` 把 zoom 敏感项并入身份哈希），建议把 DPR 移出身份哈希、只作软信号。

## 8. 测试清单

算法单测（`internal/domain/iprisk`）：单类型不封（7 例）/ 同类型反复不封 / 两类弱证据 80 不封 / 多证据互证封（4 例）/ 强证据单类累积封 / 共享出口稀释保护 / 中等速率单人只观察 / 稀释只作用弱类 / 稀释边界 / 半衰期数值与过期丢弃 / 0 分宽限事件忽略 / 阈值边界（100 封、95 不封）/ 类型映射表 / 三条旧误封回归。

引擎集成（`internal/interfaces/httpapi`）：密钥轮换不封且改记 `id-token-stale` 并重签 / 结构非法仍即时封 / 单条环境核验不封 / 单一类型反复不封 / 三证据互证封 / 三条不同环境 flag 互证封 / 不同 flag 独立记账且同 flag 去重 / 共享出口稀释不封 / 封禁墙 404 与 ipguard 自救通道放行。

## 9. 活体验证（本地实例实测，2026-10-05）

对运行中的服务上报 `POST /api/v1/fp/report`：

| 操作 | 旧实现 | 新实现实测 |
|---|---|---|
| 单条 `headless-ua` | `severe` → 立即封 7 天 | **不封**（仅记 50 分观察） |
| 三条互证（headless-ua + navigator-webdriver + automation-global） | 立即封 7 天 | **封，但为初犯档 30 分钟**，理由「多证据互证：有效分 120（3 种类型）」 |

活体验证还暴露并修复了一个设计缺陷：所有环境 flag 原先共用 `env-flag` 这一个 kind，
5 分钟去重把三条互证压成一条，互证永远无法成立（详见 §5.7）。
