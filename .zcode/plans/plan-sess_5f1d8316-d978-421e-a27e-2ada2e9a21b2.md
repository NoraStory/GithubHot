# 渗透测试修复计划（M-1..M-4 / L-1..L-6，按依赖顺序三阶段）

## 阶段一：代码修复（一批提交 → CI → 部署）

### 1. M-4：gh_id 令牌 v3 = AES-256-GCM 加密（`ipguard.go:590-655`）
- 签发改为 **v3**：`v3.<b64url(nonce||密文)>`，载荷 `ip|fp|issued|exp` 用 AES-256-GCM 加密，密钥 = `SHA-256(g.key ‖ "gh-id-aead-v3")`（纯 stdlib，无新依赖）——Cookie 被窃无法解码 fp，跨 IP 接管路径（`ipguard.go:1107-1111` 宽限）失去 fp 来源
- 核验：先试 v3（AEAD 解密），失败且前缀 v2 → 走旧 HMAC 路径（兼容过渡，不杀存量会话）；tokenStatus 三态语义不变
- 单测：v3 签发→核验往返、v2 老令牌仍可验、篡改 = tokenMalformed

### 2. M-3：ALTCHA 已解挑战消费账本（`altcha.go`）
- 内存 `consumedSet`（map+互斥锁+惰性过期清扫，TTL=`altchaMaxAge()`，风格仿 attest.NonceStore），键 = `SHA-256(challenge|nonce)`
- `checkAltchaForReport` 与 `altchaVerifyAPI` 在 Verify 成功后 `Consume`：已消费 → 401「解已被使用」+ `altcha-replayed` 计分事件；消除 10 分钟重放窗口
- 容量守卫：超 65536 条先清过期；注释注明多副本部署时应换共享存储（cache 包已备）

### 3. M-2：管理端登录接 PoW + 文案去敏
- `auth.go` `loginPayload` 加 `Altcha` 字段；`adminLogin` 在 `altchaEnforced()` 时要求有效解（失败 401，**不计入**爆破锁定次数）；未启用时行为不变（本地开发无感）
- `web/src/lib/api.js` `adminLogin` body 加 altcha 字段；`AdminLogin.vue` 用现成的 `deviceFp()` + `solveAltcha(fp)` 求解（挑战端点已校验 fp 长度 16-128）
- `altcha.go:44/70` 错误文案去敏：对外统一「服务暂不可用」，细节只进服务端日志

### 4. PoW 执行的 APP 兼容（`checkAltchaForReport`）
- 请求带 `X-App-Sign` 头即跳过强制：AppGuard 中间件已在上游验证（无效签名 403，到不了这里），存量 APP 不被误伤；非 APP 流量照常强制

### 5. 指纹体系信任分级（components 污染，`FingerprintMeta` 加 `Trusted bool`）
- `fpReportAPI`：trusted = 持有效 gh_id 会话（`verifyIDToken`）或带 `X-App-Sign`（上游已验签）
- `ip_guard.go` `UpsertFingerprint`：**行已存在且 !trusted → 完整保留旧 components**（忽略上报值，换脸检测基线不可被匿名覆写）；首报（无行）照常建档
- 波及更新：`guard_store.go` 适配层、`appguard.go:322` APP 直调（有验签 → trusted=true）、相关测试
- webrtc/flags 的 append-only 累积本次不动（范围收敛在报告指出的 components 基线）

### 6. L-2：`realIP()` 收口
- 唯一调用者 `devtoolsDetectedAPI:538` 换 `clientIPFromRequest`；删除 `realIP` 函数（注释里承认的遗留模式）

### 7. L-5：X-Device-Fp 长度上限
- 两处读取点（`ipguard.go:832` 中间件、`appattest.go:125`）：>128 字节一律按空处理（不截断，避免指纹绑定错乱；空 = 导航级请求，不计分）

### 8. L-6：`IP_GUARD_SECRET` 设置但 <32B → serve 拒绝启动
- 在 `cli.go Serve` 开头检查（区分"未设置"=开发模式随机+警告不变、"设置了但过短"=配置错误红线），不改 `NewIPGuard` 签名避免波及测试

### 9. L-1：安全响应头中间件（`server.go:60` cors 之后插入，404/封禁响应也带头）
- `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、`Content-Security-Policy: frame-ancestors 'none'`
- **不加** script-src（index.html 引用 elemecdn/jinrishici，强 CSP 会弄坏站点）；API 缓存类端点保持现状（公开数据 + X-Cache 是有意设计）

### 10. devtools-detected 约束
- 必须带合法长度 `X-Device-Fp`（否则 400）+ 每 IP 1 次/分钟小限流（仿 `appDlAllow` 模式），污染灌账本不可行
